I'm applying for the Creative Technologist, Digital and Design role, which includes owning MATTE's website. So I spent some time with it, the way I would in my first week.

The site already has a strong point of view: the full-bleed film hero, the editorial type, and the decision to put the studio's community on the homepage next to the client work. These notes are about helping that work land, starting with pacing and ending with a few fixes that would take an afternoon.

01 / Experience

Scroll pacing

The hero is the only part of the homepage that makes you pause. Everything after it moves past at the same speed, so the featured work goes by as fast as the footer.

The opening film sits in a 150vh section with a sticky frame, so the first scroll holds you on MATTE's reel. It's a confident start. After that the page is a flat feed, and the two featured projects (MERCURY and VIBECON) can be passed in a single flick of the trackpad.

Giving each section its own short beat, the way the hero already does, would turn the homepage into a guided path through the work. The site already runs Lenis smooth scrolling and uses position: sticky, so this builds on what's there rather than adding a new framework.

What a beat would be

  • Featured projects: each pins for about one screen of scroll. The video plays full-frame while the title and tags come in, then it releases into the grid.
  • Section titles ([ What We Make ], [ What We're Up To ]) become short title cards, the way chapters open in a film.
  • The rest stays free. The grid, the CTA and the footer keep normal scrolling, so the pauses feel chosen rather than slow.

Guardrails

  • Visitors with prefers-reduced-motion set get plain scrolling with no pins.
  • On phones, beats are shorter (about half a screen) so the page never feels stuck.
  • Prototype it in Figma or a branch first, then test it with someone who has never seen the site before shipping.
High impactDesign + front-end~1–2 week sprint
02 / Content design

Let the community read as community

Putting the events MATTE hosts and attends on the homepage is a great idea. Showing the studio's community says something about the brand that a project grid alone can't.

The issue is that [ What We're Up To ] uses the same card as the project grid: a poster-sized image, an uppercase title and a small label. When you scroll quickly, a party at Art Basel Paris looks like a client project. It's also the tallest section on the page (1,976px), and events and editorial articles are mixed in one grid.

Giving it its own visual language, one built around dates the way a calendar is, would make the difference clear at scrolling speed and give community its own role in the brand story.

03 / Content state

Past events still say RSVP

Five of the six events on the homepage have already happened, and all six show an RSVP button.

When a visitor taps RSVP for something that happened in May 2025, the site looks unattended, which works against the community message in note 02. The CMS already stores a date on each event, so the site can switch the button automatically and nobody has to remember to update it.

Fix · derive the button from the date

// one rule instead of manual edits
const isPast = event.date < todayInNY()

cta = isPast
  ? (event.recap ? "See recap" : "Photos")
  : "RSVP"

// and sort: upcoming (soonest first),
// then past (newest first)

This could go further: once an event passes, an AI step could draft a short recap from the event's photos and press for the team to approve.

04 / Bug

Dates shift by one day

The 8-Ball Benefit is dated 11/20/26 in the page the server sends. A moment later, after the JavaScript loads, the browser shows 11/19/26.

The same thing happens on other cards (for example, 11/04/25 becomes 11/03/25). This is a common time-zone bug. A date with no time, like 2026-11-20, is read as midnight UTC, which is still the evening of the 19th in New York, so anyone in the Americas sees the wrong day. The server and browser also disagree, which causes a React hydration mismatch.

What visitors see

CardServer HTMLAfter load
8-Ball Benefit11/20/2611/19/26
Creative Expression in the Age of AI11/04/2511/03/25

Seen in Chrome on a machine set to US Eastern time.

Fix · format date-only values as dates, not instants

// before (probably): new Date("2026-11-20") → Nov 19, 7pm EST
// after: format it in UTC so the day never moves
new Intl.DateTimeFormat("en-US", {
  month: "2-digit", day: "2-digit",
  year: "2-digit", timeZone: "UTC"
}).format(new Date(event.date))
Quick winFront-end~1 hour
05 / Accessibility + search

Headings and alt text

The homepage has no headings in its HTML, and none of its 37 images have alt text.

The bracketed section labels look like headings but are marked up as plain text. As a result, screen-reader users can't jump between sections, and search engines have less to work with when deciding what the page is about. Missing alt text also means MATTE's best work is invisible to anyone using a screen reader, and to image search.

Measured on the homepage

Heading elements (h1–h3)0
Images37
Images with an alt attribute0

Fix · markup now, alt text built into the CMS workflow

  • Render "MATTE" as the page's h1 and the bracketed labels as h2s, with no visual change.
  • Add a required alt field to the image type in Sanity.
  • Use AI to draft the alt text when an image is uploaded, and have an editor approve or adjust it. That covers the existing library in one pass and keeps new uploads covered.
Quick winFront-end + CMS + AI~1–2 days
